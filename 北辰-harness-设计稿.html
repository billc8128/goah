北辰 Harness

长期运行、对可度量大目标负责的 multi-agent 系统。用户给一个目标(如"收入 $500k/天"),系统自主拆解、执行、检查、修正;仅危险动作与预算越线时请求人工。

1背景与问题

现有 agent 产品(Claude Code、Manus、AutoGPT 等)在部署与交互形态上各不相同,但生命周期同构,都是 session 级:人交来一个任务,agent 带工具自主循环直到做完,人验收,状态活在上下文里,运行结束即终结。编排框架(LangGraph、CrewAI 等)提供了跨步骤的结构,但拓扑由开发者预先写死,运行时不能自主 re-plan。对照"对一个指标长期负责"所需的能力:

所需能力现状
状态在进程外持久上下文即状态:session 结束即丢,或依赖压缩摘要(有损、不可追问)
自主唤醒与调度每次运行由人或外部 cron 发起;agent 不会自己定闹钟、不会被指标叫醒
独立纠错反思由同一个上下文里的自己做;无角色读全量事实对账
目标 / 指标 / 预算语义目标是一个 prompt 字符串;无分解结构、无达成判定、无预算约束
无人值守的安全边界靠人盯着逐动作确认(permission prompt),或干脆全放开

dsh(2026 开源)是最接近的先例:账本、整值事件、崩溃语义可直接借用(§9);但其 authority wall 有意禁止无人值守恢复自主,且无目标分解、常驻调度、独立验证——差距在定位,不在工程。

长期无人值守要解决五个问题(后文原则、模块均回指这五项):

  • A 上下文增长:持续 session 的上下文随时长线性膨胀,模型退化;这是长跑不成立的首要工程原因。
  • B 漂移:错误归因被写进记忆当作事实,后续决策基于它,错误复利;agent 反思自己的工作时倾向自我辩护,纠不回来。
  • C 崩溃与副作用:进程随时可能死;外部动作(花钱)不可重放,恢复时可能重复执行。
  • D 安全边界:无人值守 + 真实预算下,靠 prompt 约束模型不成立,约束必须机械执行。
  • E 人工带宽:人不能成为调度器或逐事审批者,否则退化回任务型;人工介入目标 ≤ 每日一次看板 + 危险动作审批。

非目标:通用对话助手;实时人机协作;一次性任务执行;模型能力本身的提升。

2设计原则

原则内容针对
P1 账本为本体系统的本体是账本,agent 是短命计算:每次唤醒 = 装载 → 干活 → 写账 → 进程死亡。上下文每轮从状态重建,天然有界;崩溃恢复 = 重放账本,与正常唤醒同一条路径。A · C
P2 目标单向下达任何回路不能改写自己的目标,目标只能由外层(最终是人类)修改。agent 的自主性限于方法层,不含目的层——系统无法用漂移后的目标为自己辩护。B
P3 验证独立于执行验证角色不在指挥链中,输入与执行者隔离(审计禁读一切自述)。验证产出落账并强制进入被审计者下次装载,不依赖对方自觉。B
P4 判断归模型,效力归状态机开放式判断(拆解、选方法、归因、审计)由模型做;判断的后果(拒绝动作、硬停、拒绝退出)由确定性代码执行。能被推理绕过的护栏等于没有。D
P5 事前闸门最小化只拦事后纠正不回来的(钱、不可逆),其余默认放行、交给事后验证层。审批面越大,系统越退化为人工工作流。D · E

3核心规则

以下规则由 harness 代码强制,不依赖 prompt:

  1. 所有持久状态在账本(SQLite)。agent 进程无状态:唤醒时装载,退出前写账,进程销毁。重启系统 = 重放账本。
  2. 事件只追加。历史压缩只做位置替换,保留 source_seqs 指回原事件,不删除。
  3. 目标节点只能由父层修改(根节点 = 人类)。每个目标节点必须有可判定的达成条件和独占指标。
  4. 每个动作必须携带 reason 与证据指针(evidence[seq]),schema 强制非空。验证角色对动作补充 audit_advice;未确认的 advice 由 supervisor 强制注入该 agent 的下次装载,不依赖其主动查看。
  5. 危险清单内的动作(超预算线 / 不可逆)挂起待审批;清单外默认放行。清单修改需人工批准。
  6. 每个 agent 有心跳契约(最长静默时间)。违约时 supervisor 强制唤醒 CEO;连续违约升级人类。

4总体架构

系统 = 一本账 + 一组时间常数不同的控制回路 + 一个独立验证平面 + 一个无模型的常驻核心。所有 agent 共用同一个执行原语(唤醒循环,§6.1),区别只在角色 prompt、装载内容和写权限。

4.2 部署视图:进程与通信

常驻进程只有 supervisor 一个;agent runner 每次唤醒起一个、退出即销毁;面板只读。不引入消息队列、缓存、独立调度器——调度表与信箱就是 SQLite 表,轮询足够,中间件只会多出必须保活的组件。

supervisor 内部服务职责触发
调度器扫 schedule 到期项、未读 decision/emergency 信件、指标越线;经 wakes 表以事务领取(lease_until),同一 agent 并发 = 1,崩溃后过期 lease 可安全重领轮询(秒级)
进程管理器拼 spawn 配置(角色 prompt + 工具集 + 装载上下文)、起 runner、超时终止、收退出码与交接调度器
账本写入器系统唯一写口:校验 schema 与写权限、分配 seq、串行落盘RPC / 交接回收
闸门危险清单判定、R4(reason/evidence 非空)检查、挂起与审批队列管理submit_action
动作执行器持全部外部密钥,按 scope 下发给 connector 受限子进程代执行(§8.2);幂等键去重;崩溃后 unknown 对账闸门放行 / 人工批复
看门狗 / 指标采集心跳契约检查、拉取外部指标写入账本、越线触发唤醒定时

其余组件均非必需常驻:面板可退化为定时生成的静态页;审批入口可复用面板 + 推送通知;指标采集不单列进程。

4.3 模块必要性

每个模块对应一个具体失败模式;"删掉会怎样"是该模块的存在证明:

模块作用删掉会怎样
目标树 + 子 agent 分层子目标边界 = 上下文边界。每个子 agent 独占一个子目标和一个指标,装载只带自己命名空间的结论单 agent 必须装下所有领域的状态,装载无法压在几千 token,问题 A 从正门回来;指标告警没有唯一责任人;一个领域的失败污染全局上下文
CEO 与子 agent 分开全局(树、预算、跨子目标取舍)与局部(单指标的方法选择)是两种时间常数和两种上下文同一个 agent 又管拆解又管执行,装载必须同时装下全局和细节;re-plan 和日常执行互相打断
supervisor(无模型)调度、闸门、密钥、写账序列化的唯一承载闸门若含模型则可被推理绕过(违反 P4);密钥若发给 agent 则清单可被绕开;无常驻方则没人执行"到点唤醒"和看门狗
actions 记录义务 + 审计批注每个动作携带 reason 与 evidence[seq];verifier 在动作上补充 audit_advice,未确认者强制进下次装载动作只剩 payload,判断不可追问、不可证伪,验证层失去原材料;审计意见无处落地,送达靠 agent 自觉
verifier(session 级)拿 trace 对照交接自述,高频、便宜自述与实际的偏差("实验正向"/样本量 30)无人发现,污染的交接直接成为下轮任务清单
全局审计(周期级)跨 agent 独立重建归因,禁读自述单 session 看不见的混杂因素(别的 agent 记的大促事件)无人核对;执行者的错误归因无对手方,问题 B 复利
mailbox + schedule短命进程间的异步通讯与"主动性"的物理载体(自约唤醒、告警唤醒)短命进程无法同步通话;无 schedule 则唤醒只能靠外部 cron,agent 失去自定节奏;消息不落地则父进程重启期间丢信
危险清单 + 幂等网关不可逆动作与钱的事前闸门;崩溃后 unknown 对账不可逆错误无法由验证层挽回;崩溃重试导致双花(问题 C)
只读面板人直读事实与指标,不经 agent 转述人的检查退化为读 agent 写的日报,叙事与数字背离时无从发现(问题 E 的看板一环失效)

5状态模型

单写者 SQLite(WAL)。agent 不直接写库,写请求经 supervisor 序列化。大块产物(报告、素材、代码)放 workspace 文件树,表里只存索引。

表可变性字段
events只追加seq · ts · agent · kind · data(JSON,整值快照) · wake_id
goals仅父层,CAS(revision)id · parent_id · objective · metric · target · owner · budget · phase · revision
schedule本人 + supervisorid · agent · next_wake_at · reason · set_by
wakes仅 supervisorid · agent · trigger_ref · status(queued|leased|running|done|abnormal|merge_blocked) · lease_until · attempt · started_at · ended_at
mailbox追加 + 已读标记id · to · from · level(fyi|decision|emergency) · body · read_at
actions状态机;audit_advice 仅验证角色写id(幂等键) · agent · kind · payload · reason · evidence[seq] · gated(bool) · status(requested|approved|dispatching|confirmed|failed|unknown) · reconciled_at? · external_ref · audit_advice · advice_acked(bool)
  • 整值事件:状态变更事件携带完整变更后快照,重放为后写覆盖(借用 dsh)。events 是唯一事实源,goals / wakes / actions / schedule / mailbox 均为可重建投影;supervisor 在同一 SQLite 事务内追加事件并更新投影,崩溃恢复 = 重放(R1 的承诺由此成立,而非仅审计日志)。
  • 长期记忆是 workspace 里的笔记文件,由 agent 在写账阶段自行整理,框架不规定其内部结构,不设独立的整理角色;装载时笔记随交接一起进入上下文。agent 退出后,supervisor 将该轮 workspace 变更提交为一个 git commit(以 wake_id 标记)——笔记 diff 由此派生,不靠 agent 自报。每次 wake 在独立 git worktree 中工作,正常交接后由 supervisor 串行合并入主干(合并前 rebase);冲突时该 wake 标 merge_blocked,不自动覆盖,交原 agent 重做或升级处置。abnormal wake 的 worktree 不合并,原样留作取证。同一 agent 同时最多一个 wake(wakes 表保证);共享黑板的写入经 supervisor 代写。
  • 未确认的 audit_advice 强制进入下次装载(带证据指针),防止同一错误被重新推导;agent 确认(advice_acked)后转为按需查询。
  • goals.budget 可选:并非所有目标涉及钱,钱的硬闸本体在危险清单与 connector 参数约束(§8)。配置了预算的目标额外获得:超线挂起、耗尽上报、子目标分配总和 ≤ 父层的检查;额度按 approved 预占、confirmed 转实际、failed 释放、unknown 期间持续占用——防止多个已批动作并发超支。
  • 单次唤醒默认设 token 与 wall-clock 上限(按角色可配置):超限强制交接、经 next_steps 链式唤醒续作。不可分段的超长单 session(深度调试、大重构,10h+ 量级)靠 runner 内 mid-turn compaction 支撑——压缩只改发给模型的视图,不改账本。
  • goals.metric 是轻量契约:数据源 · 统计窗口 · 方向 · 目标值 · freshness(数据多旧算失效),达成判定可机械执行。独占指标 = 责任归属(告警有唯一响应者),不是因果独占。可选字段:sustain_for(持续达标时长)、guardrails(主指标改善时不得突破的保护指标)。
  • events / 交接 / workspace 笔记上建 FTS5 索引(SQLite 内建),供 verifier 与全局审计检索。runner 对账本的唯一职责是无损吐事件;事件入账后,runner 本地 session 文件为可丢弃的中间产物——账本是唯一 record。

5.1 跨 agent 状态可见性

agent 之间不互相推送状态,也没有点对点同步:最新状态就是账本本身。装载时默认只带自己命名空间;需要他人状态时按需只读——目标树(全局公开)、他人交接与笔记、workspace 黑板。写侧全部经 supervisor 串行化,events.seq 全局单调,读到 seq N 即读到了 N 之前的完整历史。所以"全局 git"已经存在:events 是不可变历史,goals 是当前树,goals.revision 提供并发写保护(CAS)。workspace 产物目录建议直接初始化为 git 仓库,免费获得版本、diff 与回滚。

6执行模型

6.1 唤醒循环(唯一执行原语)

写账阶段固定输出(schema 校验,不合规不放行退出)。接近 token / 时长上限时进入交接保留区:预留 handoff 专用预算,停发普通工具调用、只允许交接,仍无合法交接则标 abnormal。交接强制只约束正常退出:kill / OOM / 崩溃时该 wake 标 abnormal,已落账事件保留,下轮装载附异常标记与未交接的事件切片:

handoff {
  observations: []     // 本轮观察到的事实要点
  results: []          // 做了什么、结果如何
  next_steps: []       // 下轮计划(成为下次定时唤醒的任务清单)
  blocker: string?     // 卡在哪
}
mail: []               // 分级投递
next_wake_at: ts       // 自约下次唤醒

6.2 触发器与装载

上下文 = 角色基座(随角色固定)+ 触发增量(随触发器)。醒来时一并消费全部未读信件;fyi 级不触发唤醒。

7验证

verifier(session 级)全局审计(周期级)
触发session 落账,且本轮提交过动作;纯只读 session 抽验周期定时;危险清单动作待批;外部指标异动
输入该 session 的交接 + trace + 动作的 reason/evidence + 本轮笔记 git diff两阶段:先仅凭事实与外部指标独立成判;后揭示动作 reason,查遗漏与冲突。全程禁读交接与笔记
核查内容自述 vs 事实:声称的结果 trace 里有没有;reason 与证据是否支撑动作;写进笔记的判断 trace 里有没有依据结果 vs 世界:独立重建归因,找 reason 未引用的反例事件(混杂因素、同期变更)
输出actions.audit_advice;违规事件落账audit_advice(附证据)、直达人类的告警
覆盖策略高频全查(动外部者);观测成本占比后再定降级抽查,按赌注加权:大注必查、高频动作优先、其余抽样

意见的送达不依赖 agent 自觉:未确认的 audit_advice 由 supervisor 强制注入该 agent 下次装载(R4);确认后转为按需查询。

8闸门与安全

8.1 危险清单(唯一事前闸门)

事后可纠正的错误交给验证层,不设事前审批。闸门是框架机制,清单内容是应用配置——框架不内置"哪些动作安全"的结论,风险由 connector 能力清单声明(§8.2),未声明者默认挂起。清单只含事后纠正不回来的两类,以下为本应用的配置示例:

类别例子处置
默认(清单外)拉数据、写结论、发实验素材、调出价、开灰度、跑 A/B直接执行
钱单笔或当日累计超该子目标预算线;预算耗尽挂起 → CEO 批;耗尽硬停 → 升级人类
不可逆签约、对外承诺、改核心定价、删数据、申请新账号/权限挂起 → 人类审批队列
  • 批复本身是动作:同样携带 reason 与 evidence[seq]、同样被审计;全局审计在大注放行前必查其证据链(§7)。
  • 挂起的是动作,不是 agent:提交后 session 正常继续/退出,批复走信箱回来。
  • 接入新能力时由人工划定其危险动作;修改清单本身需人工批准(R5)。
  • 系统外兜底:支付用带限额的虚拟卡;投放账户用平台侧预算上限。agent 无修改入口。

8.2 幂等与崩溃

  • 外部动作经 connector 执行。connector 是受限子进程:supervisor 按声明的 scope 只下发该 connector 的密钥,不在自身进程内运行 connector 代码;agent 进程永不持有任何密钥。
  • 每个 connector 带能力清单(capability manifest):是否原生幂等 · 结果如何查询 · 可否自动重试 · 风险声明与参数约束(账号 / 环境 / 金额 / 频率)。未声明能力的动作默认挂起(fail-closed)。
  • 动作携带 actions.id 作幂等键;dispatching 中崩溃(含 supervisor 崩溃)恢复后一律标 unknown。对账不是终态而是获得结果的方式:查询外部实际状态后回到 confirmed 或 failed,reconciled_at 记录对账时刻。unknown 默认只允许对账;仅当 connector 声明原生幂等时才允许自动重发。

8.3 Computer use

  • 有 API 的能力一律走 API;computer use 仅用于无 API 的界面。
  • 浏览器会话挂受限子账号(CMS 草稿角色、设上限的投放子账户、只读财务),使危险操作在该角色下不可表达。
  • 会话操作流全程落账,verifier 事后对照申请意图。
  • 提权 = 人工亲自操作,或授予一次性提权会话。

决定:采用 pi-agent-core(2026-08-18 拍板)。判定依据是本系统的进程模型:每唤醒一进程、每进程一个 agent、spawn 配置由 supervisor 拼装。在此模型下,dsh 最强的机制解决的是我们没有的问题——scope 遮蔽服务于同一运行时内多 agent 共存(我们的角色组合 = 一份 spawn 配置);事件同源只是导入账本时的映射便利(pi trace 同样完整)。所需能力在 pi 中的落点:闸门 = beforeToolCall / shouldStopAfterTurn 钩子;交接强制 = handoff 工具 + terminate + provider 端 strict;compaction = 照 Codex mid-turn 设计在 transformContext 实现,支撑不可分段的 10h+ 单 wake;trace 经官方 SQLite backend 或 JSONL 映射入 events 表。借 dsh 的四个设计(整值事件、位置替换、unknown 语义、交接 schema)全部落在 supervisor / 账本层,与 runner 无关,不需要 runner 具备插件系统。

风险管理:pin pi 0.x 版本;runner 以防腐层包装(接口只暴露 spawn/结果/事件流,可整体替换)。dsh 为备选,适用条件:想零成本获得现成工具集与结构化输出插件(约 3–6 人日跑通),代价是 pin v0 格式 + Cordis 学习面 + 秒级冷启动。dsh 的本命场景是有人值守的深度定制交互式 agent 应用与高取证要求的会话系统,与本系统的无人值守目标正交。codex exec 不适合当通用 runner(定制面窄),但其 mid-turn compaction 与 outputSchema 为直接抄的设计参照。自迭代不构成选型差异:自写工具经账本注册、下次唤醒 spawn 时注入,任一 runner 均支持;session 中途热改运行时是审计盲区,不采用。

  • 进程:supervisor(常驻)+ agent runner(每唤醒一进程)+ 只读面板(直读 SQLite,不经 agent 转述;首版可为静态日报页)。
  • supervisor 独立进程,不作任何 runner 框架的插件:看门狗必须在被监督者的故障域之外,否则看门狗死掉无人发现。runner 侧的 harness 逻辑(闸门客户端、交接强制、事件导出、compaction 策略)则以 runner 插件形态承载——插件是伸进每次唤醒的手,supervisor 是唤醒之外的地面。
  • 存储:单写者 SQLite WAL + workspace 文件树。
  • 借用 dsh 的设计(不用其代码):整值事件 + fold 投影;位置替换式压缩 + source_seqs;outcome: unknown 崩溃语义;Ralph 结构化交接 schema。
  • 不基于 dsh 开发的原因:其 authority wall 刻意禁止跨重启自主运行(恢复必须有真人消息),与本系统目标冲突;会话格式 v0 无迁移承诺。

12开源形态

按开源框架设计,同仓附一个官方参考应用。定位:"a long-running, goal-oriented agentic system"。与 runner 互补:runner 管单次会话,本框架管进程、状态、闸门、审计。许可 Apache-2.0。

12.1 包结构

框架只提供机制(规则的机械执行);角色组合是配置,§4.1 的角色表移入 examples/。monorepo,按依赖切包:

包职责
ledger-contract五表 schema、R1–R6 不变量、装载/交接 schema、类型定义。无存储实现、零运行时依赖
ledger-sqliteSQLite 参考实现(WAL、FTS5、迁移工具),过契约一致性测试
supervisordaemon,§4.2 六服务。红线:进程内不执行用户插件或 agent 提供的代码
runner-pipi 适配器。runner 契约 = spawn 配置 + 钩子 + trace 无损导出,接新 runner 即实现此契约
testkitfaux model、模拟时钟、内存账本、故障注入。公开 API;全部测试零真实密钥
examples官方参考应用:读者可自行核验的长时程任务(如:保持仓库依赖常新、测试常绿,持续三个月)

agent 侧代码只依赖 ledger-contract,不依赖 ledger-sqlite——"agent 不碰数据库"由依赖检查执行。私有业务应用独立仓,不作公开示例。skills 采用 agentskills.io 标准。

12.2 契约管理

五个公共契约:账本 schema、runner 适配、装载协议、交接 schema、connector 能力清单(§8.2)。每个带 contract_version、stable/experimental 标注、additive-only 演进、一致性测试。

  • 账本 schema:核心表列固定,语义载荷走 JSON,扩展走附加表;迁移工具随首版发布。
  • 装载协议可替换;不可协商项:未确认 audit_advice 必须进装载(带理由与证据),原始推理链不得回灌。
  • 交接 schema 可扩展字段;next_steps / blocker 语义保留(调度器依赖)。
  • 全仓 lockstep 版本;每包 CHANGELOG,Breaking Changes 附迁移代码;架构决策记 ADR。

12.3 发布前置条件

  • 故障注入套件全绿:模拟时钟 + faux model,在每个状态转换点 kill -9,断言账本一致、动作不重放、unknown 全对上。
  • 一份真实长跑账本,脱敏后公开,可独立审计。
  • README 写明安全边界——机械保证:危险清单内的动作未经批准不执行、审计意见必然送达下次装载;不保证:模型判断正确、防御 prompt injection。
  • 默认 fail-closed:首跑 dry-run、无外部密钥、token 硬上限开启。
